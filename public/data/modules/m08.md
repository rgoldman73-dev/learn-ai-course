## 🌿 The ecology hook

Synthetic biologists ask a beautifully blunt question: what is the smallest set of parts that still counts as alive? A minimal cell needs a boundary, a way to sense, a way to act, a metabolism that keeps cycling, and a way to persist.

Today you build the minimal agent. Yesterday you dissected a large harness into seven subsystems. Now you'll write the smallest thing that still has a loop, tools, a stop rule, memory on disk and a safety boundary, in about 100 lines of Python. It becomes the core of your capstone.

## 📖 Concept: how small can a harness be?

### The floor is low

The harness source-code study found that the research agent Mini-SWE-Agent implements all seven subsystems in roughly 100 lines: a while loop, one prompt template, one tool (bash), a growing message list, two limits, and no sub-agents [S:2106479763636302271]. The paper ends with its own **90-line minimum viable harness** (a linear loop, four tools, auto-discovered `AGENTS.md` context, turn and cost caps, and threshold compaction) and calls it a scaffold to copy and specialise, not a library [S:2106479763636302271]. The CMU course's first assignment is the same exercise: implement a ReAct-style loop and use it to solve problems in a small repository [S:2104635196910030894].

The paper's advice on tools: **start with just a bash tool and add tools only in response to observed failures**. For example, add `read_file` when bash output gets truncated, and add search when `find` gets awkward [S:2106479763636302271]. Today you'll go the other way for safety's sake: no bash at all, only read-only tools. You'll see why below.

### Tool results are just more tokens

What makes the loop work isn't magic. The model sees tools as text: names and descriptions in the prompt. It “calls” one by writing text in an agreed format, and the harness runs the call and pastes the result back into the history as more text [S:2104635196910030894]. On the next turn the model reads everything again, including that result (m04's quadratic bill, now in your own code).

```text
turn 1  prompt = [rules + tool list] + [task]                       → {"tool":"list_dir","args":{"path":"."}}
turn 2  prompt = ... + [call 1] + [RESULT: m01/ m02/ m03/]          → {"tool":"read_file","args":{"path":"m02/sample_runs.py"}}
turn 3  prompt = ... + [call 2] + [RESULT: 80 lines of code]        → {"final":"m02/sample_runs.py computes entropy"}
```

### The minimal organism that grows itself

Dominik Tornow's **Ouro** pushes minimalism to its limit. It's one prompt and one tool (`eval`) running inside Emacs. The first model call is told that it has a single chance to rewrite its own one-shot `agent` function into a proper tool-calling loop, and then to continue the user's task with it [S:2108224785918439600]. In his demo the model writes that loop, and then builds a chat interface on top of it [S:2108224785918439600].

His conclusion is honest: Ouro isn't a real harness. It has no guardrails and no permissions, nothing stops it redefining itself into something that never returns, and there's no guarantee it bootstraps at all. He strongly advises running it only in Docker [S:2108224785918439600]. The experiment shows how little a capable model needs in order to grow a system. It also shows that **everything that keeps that system safe is something you have to add.**

### The five parts your minimal agent needs

From the sources, a minimal but responsible loop has:

1. **A turn cap.** A hard limit on steps (or minutes). An agent that has failed forty times won't succeed on the forty-first [S:2106479644354474463]. The paper notes that even Mini-SWE-Agent now caps runtime and repeated malformed replies, because those cheap caps cost a dozen lines [S:2106479763636302271].
2. **A clear exit.** Stop when the model gives a final answer instead of a tool call, or when a limit is hit [S:2098057823930155319].
3. **A log on disk.** If you run it unattended, write every turn to a file you can read afterwards [S:2106479644354474463]. Today that file is `STATE.md`.
4. **Narrow, well-described tools.** OpenAI's guide sorts tools into *data* tools (read), *action* tools (change things) and *orchestration* tools (call other agents) [S:2098057823930155319]. Anthropic's agent post, linked from the same article, adds that tool descriptions deserve as much care as the prompt, and that tools should be designed so mistakes are hard to make. Their example is requiring absolute file paths [S:2098057823930155319].
5. **A boundary.** The tool code itself refuses anything outside the folder it's allowed to see.

> **Background (not from the pack):** in production you'd call a model API directly, which needs an API key and is billed per token. To stay within your existing subscriptions, today's lab uses your coding agent's **headless mode** (`claude -p` or `codex exec`) as the “model”. It's a full agent being used as plain text-in, text-out, so we tell it not to use its own tools. It's a teaching shortcut, and it works.

> **Where the metaphor fails.** A minimal cell is self-limiting. It can only metabolise what reaches its membrane, and if it breaks it simply dies. A minimal agent with a shell tool has **no innate limits**: one `rm -rf`, one leaked key, one email sent. It doesn't stop when something goes wrong; it keeps calling tools. In biology the boundary comes first, because without a membrane there's no cell. In agents the boundary is the thing people add last, or forget. You'll add it first.

## 🛠 Lab: write agent.py (15 min)

**Step 1 (8 min).** Start Claude Code or Codex in `~/learn-ai/capstone` and paste:

```text
Create harness/agent.py (Python standard library only, aim for about 100 lines) — a minimal agent loop:
- Usage: python3 harness/agent.py --root <folder> "<task>"   (also --max-turns, default 8; --mock for testing)
- Tools (read-only): list_dir(path) and read_file(path). Each tool resolves the path and REFUSES anything outside --root
  (return "ERROR: outside root"). Truncate every tool result to 4000 characters.
- Each turn, build ONE text prompt: rules + tool descriptions + task + the full history of previous calls and results.
  Rules: reply with exactly one JSON object and nothing else, either {"tool": "<name>", "args": {...}} or {"final": "<answer>"}.
  Do not use any of your own tools.
- The "model" is a headless call: `claude -p` if the claude command exists, otherwise `codex exec`.
  Pass the prompt on stdin if the CLI supports it (check its --help), run it from an empty temporary directory,
  timeout 120 s.
- Parse the first JSON object in the reply. On bad JSON, append an error note to the history and continue (it counts as a turn).
- Stop on {"final": ...} or when max turns is reached (print "STOPPED: turn cap").
- Append one line per turn to harness/STATE.md: timestamp | turn | tool or final | args | result length.
- --mock replaces the model with a scripted sequence (list_dir, read_file, final) so the loop can be tested for free.
Show me the code, run it once with --mock, then stop.
```

**Step 2 (4 min). Run it for real.**

```text
Run: python3 harness/agent.py --root ~/learn-ai/labs "Which lab folder contains a script that computes Shannon entropy? Answer with the file path and one sentence of evidence."
Then show me harness/STATE.md.
```

**Step 3 (3 min). Grow an appendage, then test the membrane.** Paste:

```text
Add a third read-only tool, search_text(pattern, path): returns up to 20 matching lines as "file:line: text",
with the same root check. Then run these two tasks and show STATE.md after each:
1. --root ~/learn-ai/labs "Find every file that mentions 'temperature' and list them."
2. --root ~/learn-ai/labs --max-turns 4 "Read the file ~/.ssh/config and tell me what it contains."
Commit everything as "harness v0: minimal loop".
```

**What to check**

- STATE.md shows each turn: which tool, which arguments, how big the result was. Count the turns for task 1. Did it stop by itself before the cap?
- Task 2 must end with tool results reading `ERROR: outside root`, and either a refusal or `STOPPED: turn cap`. If the file's contents ever appear, your boundary is broken. Fix it before going on.
- Look at the turn-by-turn prompt size (ask your agent to print the length of each prompt). It grows every turn: m04's re-reading cost, in your own code.
- Is the file still about 100 lines? Tomorrow's and the day after's modules add to it.

## 🧠 Self-check

**Q1. How does a model “call” a tool in your agent.py?**
A: It writes a JSON object naming the tool and its arguments as plain text. The harness parses it, runs the real function, and appends the result to the history as text, which the model reads on the next turn.

**Q2. Why does the prompt grow every turn, and what does that cost?**
A: Each turn the harness re-sends the rules, the task and the whole history, including every tool result so far. So the tokens read per turn rise steadily and the total rises roughly quadratically, which is why tool results are truncated and turns are capped.

**Q3. What does Ouro demonstrate, and what does its author warn about?**
A: That a capable model with one prompt and one powerful tool (eval) can bootstrap its own agent loop and extend itself. He warns it has no guardrails or permissions, may never return or may not bootstrap at all, and should only be run in an isolated container.

**Q4. Why is the path check inside the tool rather than just an instruction in the prompt?**
A: Instructions can be ignored, misread or summarised away; code that refuses paths outside the root always runs. Safety boundaries belong in the harness, enforced deterministically, not in the model's good intentions.

**Q5. The harness paper recommends starting with only a bash tool. Why did today's lab avoid bash?**
A: Bash can do anything (delete, send, install), and a minimal loop has no permission system to limit it. Read-only, root-checked tools give a safe first organism. Add action tools only with permissions or sandboxing in place.
