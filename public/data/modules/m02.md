## 🌿 The ecology hook

Mutation rate sets how far offspring stray from the parent. If it's too low, a lineage is stable but can't explore. If it's too high, it explores, but noise piles up and good solutions are lost. Drift adds chance on top of that, so even identical starting populations end up in different places.

A language model generating text faces the same tradeoff at every single word. Yesterday you saw how training shapes the weights. Today you'll see how a trained model **produces** text: it builds a probability distribution over possible next tokens, then a *sampler* picks one. **Temperature** is the dial that sets how adventurous that pick is, so it works like a mutation rate.

## 📖 Concept: from weights to words

### Tokens: the unit of everything

Models don't read words or letters. They read **tokens**, which are chunks of text, often a piece of a word. Ruben Hassid's guide to using Claude puts it simply: Claude counts in tokens, and each message makes it re-read the whole conversation as tokens [S:2107712638381941071]. Tokens are also how usage, cost and context limits are measured, which will matter a lot in Unit 2.

The CMU agents course describes even an agent this way: the language model itself is “tokens in, tokens out”, and everything else (tools, memory, the loop) is built around it [S:2104635196910030894].

### One step of generation

At every step the model outputs a score for every token in its vocabulary. Those scores are turned into a **probability distribution over the next token**. Then the system samples, or in some other way chooses, one token, appends it, and repeats [S:2104635196910030894].

Jeff Dean's lecture gives a nice example of what that distribution looks like. For “perform the concerto for ___”, a good model spreads probability over *violin*, *piano*, *trumpet*, and puts almost none on *airplane*. That whole distribution carries much more information than the single right answer, which is why a large teacher model's distributions can train a smaller student model (distillation) [S:2106489085829488811]. He also notes that some tokens are much easier to predict than others [S:2106489085829488811], so the distribution is sharply peaked at some steps and flat at others.

### Temperature and top-p

> **Background (not from the pack; standard definitions):** the sampler divides every score by the temperature *T* before turning scores into probabilities. *T* < 1 sharpens the distribution towards the top choice. *T* > 1 flattens it, so unlikely tokens get picked more often. As *T* approaches 0, sampling becomes **greedy**: always take the top token. **Top-p** (nucleus sampling) keeps only the smallest set of top tokens whose probabilities add up to *p*, and samples from those.

### Same word, different jobs

**For extraction and decisions, turn variation off.** The local-LLM course's code sets `temperature=0` for a routing decision and for pulling fields out of an invoice, with the instruction “Never guess a number” [S:2106761689123139973]. When an answer is checked against a schema or a ground truth, exploring is a bug, not a feature.

**Temperature also means something else: calibration.** The Kev project trains small “decision models”. Each checkpoint stores a temperature that was fitted on held-out data so that the model's probabilities match how often it is actually right. As its README puts it, a temperature never changes which answer wins [S:2101715352258232539]. Dividing every score by the same number keeps their order, so the top answer stays on top. Only the stated confidence changes. Keep this in mind for m03.

### Why outputs vary, even when you don't touch the dial

Chat apps and coding agents usually sample with some temperature, so the same prompt can give different answers. Agents make many sampling decisions in a row, so small early differences compound into different plans, much like founder effects. You often can't set temperature in Claude Code or Codex at all. The lever you *do* control is the prompt: a precise question makes the distribution sharply peaked, while a vague one leaves it flat (see the two presets in the widget).

> **Background:** even at temperature 0, hosted models are not guaranteed to be bit-for-bit repeatable, because of how requests are batched and computed on servers. Plan for variation: verify outputs instead of assuming them.

> **Where the metaphor fails.** Mutation produces heritable variation that selection then acts on across generations. Temperature only reshapes a single draw at a single step. Nothing is inherited, and nothing is selected unless *you* add selection, for example by sampling several answers and keeping the best one that passes a check (best-of-n, verifiers; Unit 8). Also, a low mutation rate in biology preserves a lineage that has already been tested by selection. Low temperature only makes the model *consistent*, not *correct*: it will repeat the same wrong answer every time.

## 🛠 Lab: measure answer diversity (15 min)

**Part A (5 min, phone OK).** In the widget:

1. On the *peaked* preset at temperature 1, press **Sample 20** three times and note the number of distinct words. Do the same on the *flat* preset.
2. Find the lowest temperature at which the peaked preset still gives at least 3 distinct words in 20 samples.
3. Set top-p to 0.5 at temperature 1.5. Which words disappear completely, and why is that safer than just raising the temperature?

**Part B (10 min, at a computer).** This runs 20 short headless calls on your existing subscription, so it uses a little of your usage allowance. In Claude Code or Codex, paste:

```text
Create a folder ~/learn-ai/labs/m02 and work only inside it.
Write sample_runs.py (Python standard library only) that:
1. Runs a headless model call 10 times per prompt and captures each answer (strip whitespace, lower-case,
   remove punctuation). Use `claude -p "<PROMPT>"` if the `claude` command exists; otherwise use `codex exec "<PROMPT>"`.
   Use subprocess with a 120-second timeout per call and keep going if one call fails.
2. Uses two prompts:
   A = "Name one animal that lives in a kelp forest. Reply with one word only."
   B = "Name the predator most often cited as the keystone species that protects North Pacific kelp forests from sea urchins. Reply with one word only."
3. Prints for each prompt: the 10 answers, the number of distinct answers, and the Shannon entropy (bits) of the answer frequencies.
4. Saves everything to results.json.
Show me the script before running it. Then run it and summarise the difference between A and B in two sentences.
```

**What to check**

- Prompt A should give several distinct animals (a flat distribution). Prompt B should collapse to one answer (a peaked distribution). Is the entropy for B close to 0?
- Ask your agent: *“Explain temperature and top-p in ASD-STE100 Simplified Technical English.”* Karpathy suggests this controlled language as a way to get explanations that are easier to read and check [S:2105819303471976479]. Is that version easier to verify than a normal explanation?
- Paste your two entropy numbers into this module's notes. You'll reuse the setup in Unit 8 when you sample several answers and select among them.

## 🧠 Self-check

**Q1. What does the model actually output at each generation step, before any word is chosen?**
A: A score for every token in its vocabulary, which is turned into a probability distribution over the next token. A sampler then picks one token, appends it, and the process repeats.

**Q2. What does temperature 0 do, and why might two runs of an agent still differ?**
A: Temperature 0 means greedy decoding: always take the most probable token. Runs can still differ because hosted inference isn't guaranteed to be exactly repeatable, and in agents any small difference early on compounds over many steps (plus tools and environments change).

**Q3. Kev stores a fitted “temperature” in each checkpoint. Why doesn't it change which answer wins, and what is it for?**
A: Dividing every score by the same positive number keeps their order, so the top answer stays the same. The calibration temperature only rescales confidence, so that “90% sure” really means right about 90% of the time on held-out data.

**Q4. You're extracting species counts from scanned field sheets. Which sampling setting do you want, and what else do you need?**
A: Temperature 0 (deterministic, no exploration) plus a schema and an instruction never to guess numbers, as in the local-LLM course's extraction example. And you still need verification, because low temperature makes the model consistent, not correct.

**Q5. Give one way the “temperature = mutation rate” analogy breaks.**
A: Mutations are heritable and selection acts on them over generations. Temperature only reshapes one draw at one step: nothing is inherited, and nothing is selected unless you add a selection step such as best-of-n with a verifier.
