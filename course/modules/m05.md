## 🌿 The ecology hook

A good field guide doesn't make you read 600 species accounts to identify one beetle. It gives you a **dichotomous key**: a few short questions (“elytra covering the abdomen? yes / no”) that route you to the one page you need. The key is small, the details are deep, and you only open what's relevant.

Yesterday you saw that context is a scarce habitat. Today's question is what to put in the one file your agent reads at the start of *every* session. The answer from the sources is unanimous: **a key, not an encyclopedia.**

## 📖 Concept: instruction files as maps

### What the file is

Coding agents load a Markdown instruction file automatically when a session starts. Claude Code reads `CLAUDE.md`. Its creator, Boris, explains that it sits in the project root, is read into context at the start of every session, and is checked into git so the whole team shares it [S:2106712905001365608]. Codex and many other harnesses read `AGENTS.md` [S:2098057823930155319]. The harness source-code study found that every system that manages repository context converged on this pattern of auto-discovered Markdown files, and the newer ones read each other's file names too [S:2106479763636302271].

What belongs in it, according to Boris and the Claude Code guide: common commands (build, test), important files and where things live, architectural decisions, style conventions the agent can't infer, and “never do this” rules [S:2106712905001365608], [S:2104402058963026288]. What doesn't: explanations of the obvious, pasted documentation, essays. The guide's rule of thumb is that a 400-line file usually performs worse than 40 well-chosen lines. It adds that if you've corrected the agent twice for the same thing, that correction belongs in the file [S:2104402058963026288].

### Why one giant file fails

OpenAI's harness-engineering team tried the “one big AGENTS.md” approach and watched it fail in four predictable ways [S:2098057823930155319]:

1. **Context is scarce.** A huge file crowds out the task, the code and the relevant docs.
2. **Too much guidance becomes non-guidance.** When everything is marked important, nothing is.
3. **It rots instantly.** Stale rules pile up, and the agent can't tell which ones are still true.
4. **It's hard to verify.** One blob can't be checked mechanically for freshness or broken links.

Their fix: a short `AGENTS.md` of **roughly 100 lines that works as a table of contents**, pointing into a structured `docs/` folder that is the real system of record. They name the principle **progressive disclosure**: the agent starts from a small, stable entry point and is taught where to look next [S:2098057823930155319].

```text
AGENTS.md  (≈100 lines: the key)
 ├─ "How is the data formatted?"        → docs/data.md
 ├─ "What are we building and why?"     → docs/project.md
 ├─ "Which decisions are settled?"      → docs/decisions.md   (append-only)
 └─ "What must never happen?"           → pinned rules, right here in the key
```

### Layers of maps

Instruction files nest, like regional keys inside a national flora:

- **Global** (your user folder), **project** (repo root), **subfolder** (loaded only when the agent works there). The more specific file wins [S:2104402058963026288].
- Nested `CLAUDE.md` files in child directories are pulled in on demand when Claude works in those directories [S:2106712905001365608].
- A **local** file (`CLAUDE.local.md`) holds personal preferences and isn't checked in [S:2106712905001365608].
- A `CLAUDE.md` can **import** another file with `@` followed by a path [S:2104402058963026288]. That lets one map serve both Claude Code and Codex: write `AGENTS.md`, then put `@AGENTS.md` in `CLAUDE.md`.
- In Claude Code, `/init` drafts a first version, `/memory` shows every instruction file currently loaded, and typing `#` adds a quick “remember this” line [S:2104402058963026288], [S:2106712905001365608].

The same idea scales beyond instruction files. LangChain describes **skills** as progressive disclosure built into the harness: only a skill's short front-matter is loaded at the start, and the body is read when it's needed [S:2098057823930155319]. You'll build skills in a later unit.

### Keep the map honest

A map only helps while it matches the territory. OpenAI didn't rely on discipline. They **enforced** the map mechanically: linters and CI jobs check that the knowledge base is up to date and cross-linked, and a recurring “doc-gardening” agent opens fix-up pull requests for stale docs [S:2098057823930155319]. Their other lesson is blunt: from the agent's point of view, **anything it can't access in context doesn't exist**. A decision made in a chat thread or a meeting is invisible until someone writes it into the repo [S:2098057823930155319].

A harness-design guide turns this into a weekend checklist [S:2106479644354474463]:

- one instructions file under a hundred lines, as a table of contents;
- anything broken twice becomes a check that fails, not another paragraph of prose;
- separate files for the spec, the plan, progress and decisions;
- rules that must never be lost go in a file the agent re-reads (yesterday's lesson).

> **Where the metaphor fails.** A dichotomous key is written once, by an expert, about organisms that don't change while you're keying them. An agent's map describes a codebase that may change every day, partly because of the agent itself. A stale couplet in a field guide wastes your time. A stale line in `AGENTS.md` gets *followed*: the agent confidently does the wrong thing because the map told it to. That's why the map needs mechanical checks, which no field guide has ever needed.

## 🛠 Lab: draft the map for your capstone (15 min)

Your capstone, at the end of the course, is a small multi-agent “ecosystem” working on an ecology problem you care about. A good default is **literature triage plus field-data quality control**. Today you create its repository (locally only, nothing goes to GitHub) and its map.

**Step 1 (8 min).** Open a terminal, run `mkdir -p ~/learn-ai/capstone && cd ~/learn-ai/capstone && git init`, start Claude Code or Codex there, and paste:

```text
This folder is my capstone repo for a course on building AI agents. Work only inside it.
Before writing anything, interview me: ask up to 6 short multiple-choice or one-line questions about
the ecology problem, the data I'll use, my conventions, and things an agent must never do. Wait for my answers.

Then create:
1. AGENTS.md: at most 100 lines. A map, not a manual. Sections: Purpose (3 lines), Repo layout,
   Commands, Where to look (one line per doc in docs/, phrased as the question it answers),
   Never (hard rules, pinned).
2. CLAUDE.md containing only the line: @AGENTS.md
3. docs/project.md, docs/data.md, docs/conventions.md and docs/decisions.md (append-only log with today's date),
   each short and filled from my answers. Mark anything you guessed with TODO.
4. scripts/check_map.py (Python standard library only): finds every file path mentioned in AGENTS.md
   and exits 1, listing the missing ones, if any don't exist.
Run check_map.py, show me `wc -l AGENTS.md`, and commit with the message "capstone map v1".
```

**Step 2 (7 min). Test the map in a fresh session.** Exit, start a new session in the same folder, and ask these one at a time:

```text
Where is the format of my field data described? Answer from the repo, and tell me which files you opened.
```

```text
What are you never allowed to do in this repo?
```

```text
I want to add a script that flags impossible species counts. Where should it go, and which doc should you update?
```

Then try to break the map. Rename `docs/data.md` to `docs/fielddata.md` and run `python3 scripts/check_map.py`. It should fail and name the missing path. Fix `AGENTS.md`, re-run the check, and commit.

**What to check**

- Did the agent answer from `AGENTS.md` plus *one* relevant doc, rather than reading everything? That's progressive disclosure working.
- Did it recite your “Never” rules correctly?
- Is `AGENTS.md` under 100 lines? If not, move detail into `docs/`.
- Did `check_map.py` catch the rename? You've just built a tiny version of OpenAI's “enforce the map mechanically” idea.

## 🧠 Self-check

**Q1. Give three reasons a single huge AGENTS.md or CLAUDE.md tends to fail.**
A: It crowds the scarce context window, so the task and code get less room. When everything is marked important nothing is, so it stops guiding. It goes stale fast and can't easily be checked mechanically, so wrong rules linger and get followed.

**Q2. What is progressive disclosure, in one sentence?**
A: Give the agent a small, stable entry point (a map) that tells it where to look next, so it loads detailed docs only when the task needs them instead of loading everything up front.

**Q3. You keep correcting the agent about the same date format. What should you do?**
A: Put the rule in the instruction file or the relevant doc (if you've corrected it twice, it belongs there). Better still, add a check that fails when the format is wrong, so the rule is enforced rather than merely suggested.

**Q4. Why does the OpenAI team say knowledge in chat threads or people's heads “doesn't exist” for the agent?**
A: The agent can only use what's in its context or what it can reach in the repository. Decisions made elsewhere are invisible to it until they're written into versioned files it can read.

**Q5. How can one map serve both Claude Code and Codex?**
A: Write the map in AGENTS.md, which Codex reads, and make CLAUDE.md import it with an @AGENTS.md line, so Claude Code loads the same content.
