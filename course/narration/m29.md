# m29 narration: Agents with bodies

Welcome to Module Twenty-Nine. This one is optional. It's a bridge between this course and your robotics course.

You know the reciprocal transplant experiment. Move each population into the other's site and measure fitness. If a population does well at home but poorly away, you've found local adaptation. Home performance didn't predict performance elsewhere.

Robot learning lives on exactly that question. Controllers are developed in simulation, where trials are cheap, safe and endlessly repeatable. Then they're transplanted to a real robot, where friction, weights, cameras and cables are all a little different. The drop in performance has a name: the sim-to-real gap.

Coding agents are now working on both sides of that transplant. The best source in the pack is a paper called SimEX. It points out two ways that agents fail with robots. If an agent writes robot code in one go, it has to guess things it can't know, like exactly where the camera is. If it learns by trial and error on the real robot, every attempt costs robot time and risks a collision.

So SimEX uses simulation as the agent's laboratory. First, the agent explores in simulation. It invents its own test tasks, finds a weakness, and improves a small toolbox of code, along with a notes file of what it has learned and where its limits are. Several independent runs explore in parallel and share ideas, a bit like an island model. Then comes a tiny real-world phase, about ten minutes of robot time per task. Each real failure is used to correct the simulator and to test fixes before the next real attempt. With that, the paper reports twenty-six successes out of thirty real trials, where the best comparison method managed three.

The authors' key insight is worth keeping. The simulator only has to get the physics roughly right, because what transfers is knowledge and procedure, not one finely tuned policy.

A second source asks which data actually teaches a robot. Its answer: only data where the robot's own policy is acting contains the robot's own mistakes. Human demonstrations, however good, can't show you how your policy fails.

Here's where the metaphor breaks. Transplanted organisms keep adapting. A controller trained in simulation doesn't. It carries a fixed gap to a world it never saw, and it may even exploit errors in your simulator, the same way a policy exploits a buggy reward.

In the lab, you'll run your own transplant on your laptop. Your coding agent builds a two-joint arm in a free physics simulator, tunes a controller at home, and tests it on a hundred new targets. Then it moves the controller into a perturbed world and gives it five trials to adapt.
