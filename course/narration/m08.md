# m08 narration: A minimal organism

Welcome to Module Eight.

Synthetic biologists like to ask a blunt question. What is the smallest set of parts that still counts as alive? A minimal cell needs a boundary. A way to sense. A way to act. A metabolism that keeps cycling. And some way to persist.

Today you build the minimal agent. Yesterday you saw that every real coding agent is built from the same seven parts. Today you write the smallest thing that still has the essential ones, in about a hundred lines of Python.

It is smaller than you might expect. One research agent, used as a baseline in serious studies, is roughly a hundred lines. A loop, one prompt, one tool, a growing list of messages, and two limits. That is it.

The secret is that tools are just text. The model reads a short description of each tool. When it wants one, it writes a small piece of structured text that says, use this tool, with these settings. Your code reads that, runs the real function, and pastes the result back into the conversation. Then the model reads everything again, including the new result, and decides what to do next.

One writer took minimalism to an extreme. His experiment, called Ouro, gives a model one instruction and one tool, the ability to run code inside its own editor. The model's first job is to rewrite itself into a proper loop. And it does. Then it keeps going, building new features onto itself. It is a lovely demonstration of how little a capable model needs to grow a whole system.

But read his warning. There are no guardrails. Nothing stops it from breaking itself, or anything else. He says to run it only inside a sealed container.

And that is where today's metaphor fails. A minimal cell limits itself. It can only use what reaches its membrane, and if something goes wrong, it dies quietly. A minimal agent has no such limits. Give it a command line and it can delete a folder, leak a password, or send an email, and it will not stop to reflect. It just calls the next tool. In biology, the boundary comes first. In agents, people tend to add it last. You will add it first.

So in today's lab, your agent gets only tools that read, never write. Each tool refuses any path outside the one folder you allow. There is a hard limit of eight turns. And every turn is written to a small log file, so you can see exactly what it did. For the model itself, you will use your coding agent's headless mode, so you do not need any new paid service.

Then you will grow it a third tool, and test the boundary by asking it to read something it should never see. If the boundary holds, you have a minimal organism that is safe to keep.

Open your terminal, and let's build one.
