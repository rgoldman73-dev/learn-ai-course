# m12 narration: Food chains to food webs

Welcome to Module Twelve.

A food chain is a line. Grass, grasshopper, shrew, owl. But you know that real communities are webs. Several consumers feed on the same resource at once. Flows split and merge. One compartment's output is another's input. And the moment you try to draw a web, you are forced to say exactly what is connected to what, and by which flow.

Yesterday you built a loop that makes one piece of work reliable. Today you draw the web around many pieces. What runs. What runs at the same time. What has to wait. Where results come together. And where they are checked. Builders call this graph engineering.

There are only two parts. A node is one bounded job, with one input and one output. An edge is a real dependency. This step's output feeds that step's input.

And here is the most useful question in today's module. For every arrow in your workflow, ask: does the next step actually read the previous step's output? Can you name the thing that crosses the arrow? If you cannot, there is no real edge. The second step was only waiting because of the order you happened to type the instructions. One writer redrew a forty-step workflow this way, cut about a dozen fake arrows, and it ran far faster, with no change to the model at all.

The vocabulary of nodes is small. A splitter cuts the work into pieces. Workers each handle one piece, in their own separate context. A plain code node merges, sorts and removes duplicates, because those jobs have one right answer and need no model at all. And a gate decides what passes.

The gate brings today's most important lesson. Do not let the worker grade its own work. Models tend to favour their own writing. So the checker must be separate, and it must start fresh, without seeing the worker's reasoning. Even then, anchor it to something real. A test that actually ran. A rule written in code.

Finally, a good graph has two ways back. A short one, which returns a single failed piece to the worker that made it, with the evidence. And a long one, which turns a lesson into a rule for how the next run is split. Almost nobody builds that second one.

Now, where does the metaphor fail? Energy flows one way down a food chain. In an agent graph, information flows backwards on purpose, and the learning edge rewrites the web itself. Nothing in nature does that. And a food web is discovered, not designed. Draw your graph too early, and you can lock in your first wrong guess.

In today's lab you will build a quality-control graph for thirty invented field records, with ten faults you planted yourself. Workers check batches in parallel, plain code merges them, rules and a fresh verifier form the gate, and a report scores which part caught what. Then you add one learning edge, and run it again.

Open your terminal, and let's draw the web.
