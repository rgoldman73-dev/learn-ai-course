# m18 narration: Learned behaviour

Welcome to Module Eighteen.

A young songbird is not born knowing its song. It listens to a tutor and stores a template. Then it practises, badly at first, a scrappy subsong, and keeps adjusting until what it sings matches what it remembers. The finished song is a learned behaviour. It can be passed on, it can vary, and over generations, the versions that get copied spread into local dialects.

Agents now have learned behaviours too. They're called skills.

A skill is a small folder with one key file in it, called SKILL dot M D. At the top, a name and a short description of when to use it. Below that, the instructions: a checklist, some rules, and the exact format of the result. It can also carry extra reference files and scripts.

The trick that makes skills work is called progressive disclosure. The agent always sees the short description of every skill it has. But the full instructions only load when the skill is actually used, and the extra files load only if they're needed. So you can keep a large library of skills, and it costs almost nothing until the moment one is called. A recent study of eleven coding agents found that this skill format is now the most widely adopted way to extend them.

You can write skills yourself. That's tutoring. And now, agents are starting to write and rewrite their own, from experience. The CMU course describes research where an agent turns its successful attempts into reusable workflows. But notice one detail. Before saving a workflow, the researchers ask a judge to check whether the attempt really succeeded. Because a remembered mistake will steer the agent wrong, again and again.

That's exactly where the songbird metaphor breaks. A bird checks its song against a template, and a population sorts good versions from bad ones. An agent that rewrites its own skills has no template and no population, unless you give it one. It can improve a skill into something worse, and then use that worse version every single time. Cultural drift, with no selection at all.

So in the lab, you'll supply the selection. You'll write a field data quality skill for your capstone, with your own hard-won rules in it, including this one: a zero count is an observation, never drop it. Your agent will plant known problems in some messy spreadsheets, and then you'll test the skill the way you'd test any intervention. With the skill, and without it. Then you'll let the agent rewrite its own skill, and check both versions on a held-out file that the rewrite never saw.

If the new version only wins on the files it was tuned on, you've just watched overfitting happen in front of you.

Open the reading, and let's teach your agent a song.
