# m05 narration: A map, not a manual

Welcome to Module Five.

Think about the last time you keyed out an insect. You did not read six hundred species accounts. You used a dichotomous key. A few short questions. Wings covering the abdomen, yes or no. Each answer sent you to the next couplet, and within a minute you were on the one page that mattered. The key is small. The detail is deep. And you only open what you need.

Today is about building that kind of key for your agent.

Every coding agent reads a special instruction file at the start of every session. Claude Code reads a file called Claude dot M D. Codex and many other tools read Agents dot M D. Whatever is in that file is loaded into the context window, every single time. And after yesterday, you know that window is a crowded, expensive habitat.

So what goes in it? The team at OpenAI that built a large product almost entirely with their coding agent tried the obvious approach first. One big instruction file with everything in it. It failed in four ways. It crowded out the actual work. When everything was marked important, nothing was. It went stale almost at once. And nobody could check it automatically.

Their fix was simple. Keep the instruction file to about a hundred lines, and treat it as a table of contents. The real knowledge lives in a folder of short documents, and the instruction file just says where to look. They call this progressive disclosure. Start small, and follow the pointers only when the task needs them.

Claude Code's creator gives similar advice. Keep the file short. Put in the commands, the important files, the conventions, and the things the agent must never do. Files can also nest, so a folder can carry its own small map that loads only when the agent works there.

Now, where does the metaphor fail? A field key is written once, about organisms that do not change while you are keying them. Your codebase changes every day, sometimes because of the agent itself. A wrong couplet in a field guide wastes a few minutes. A wrong line in your agent's map gets followed, confidently. That is why the OpenAI team checked their map automatically, and even ran an agent whose only job was to tidy stale documents.

In today's lab you will create the repository for your capstone project, the small ecosystem of agents you will build by the end of this course. Your coding agent will interview you first, then draft a short map and a few focused documents. You will add a tiny script that fails if the map points at a file that no longer exists. Then you will test the whole thing in a fresh session, and try to break it.

Open your terminal, and let's draw the map.
