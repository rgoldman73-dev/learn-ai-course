# m15 narration: Division of labour and the adversary

Welcome to Module Fifteen.

Social insects invented division of labour long before we did. Nurses, foragers, guards. Each does one job, with the tools its body gives it, and the colony gets far more done than the same number of generalists would.

There's a second idea from ecology I want you to hold on to today. Predators keep prey populations honest. The careless and the weak get culled. A system with no predator slowly drifts.

Agents use both ideas.

The first is the subagent. Think of it as a specialist worker with its own context window. It gets a short brief, does one job, and hands back only its result. That keeps your main conversation clean. And crucially, you can restrict its tools. A reviewer that can read files and run tests, but cannot edit anything, is a reviewer you can trust not to quietly fix things and call it a pass.

The second idea is the predator, the adversary. Two of today's sources describe the same three moments when it should wake up. Before a plan is locked in. When the same error comes back twice, because that is usually a sign you're hiding a symptom instead of fixing a cause. And before anyone says the word done.

Claude Code can also run whole teams, where a lead coordinates several sessions that message each other. The documentation is honest about the price. Teams use far more tokens, they suit research, review and debugging with competing hypotheses, and three focused teammates often beat five scattered ones.

Now the trap. If you put four reviewers in one shared conversation, they converge. The first one writes a finding, the others read it, and all four reports say the same thing. One of our sources calls this paying four times for one opinion with three echoes. The fix is to give each reviewer its own context and a different lens.

And this is exactly where the caste metaphor breaks. Real castes differ in genes, age and experience, so their mistakes are partly independent. Cloned agents share the same model and the same training, so they share the same blind spots. If you want diversity, you have to design it in.

In the lab, you'll build a read-only reviewer for your field data cleaning code, with three lenses: data meaning, code correctness and provenance. Then you'll plant a bug that any ecologist would hate. You'll ask the main agent to quietly drop every row where the count is zero. A zero is not missing data. It's an absence, and it matters. Let's see whether your predator catches it.

Open the reading, then go build your reviewer.
