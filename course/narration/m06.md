# m06 narration: Prompts that work

Welcome to Module Six, the last module of Unit Two.

Here is a hypothesis. Warmer streams have fewer stoneflies. It is a perfectly good hypothesis, and it is useless as a set of instructions. Before anyone goes into the field, you write a protocol. Which sites. Which method. What you will measure. How many replicates. And what result would count as an answer. Hand a field team only the hypothesis, and they will come back with something. It probably will not be what you needed.

A prompt to a coding agent is a protocol. And you are handing it to a team that is extremely fast, extremely willing, and never asks a clarifying question unless you tell it to.

So what makes a good one? One of today's guides boils it down to three parts. A goal, a scope, and a done criterion. What should be true at the end. What the agent may and may not touch. And how you will know it worked. That last part matters most. Tests pass. The output matches a reference file. Something a command can check. Without it, done just means the agent thinks it is done.

The creator of Claude Code adds two habits. First, ask the agent to make a plan and wait for your approval before it writes any code. Fixing a plan takes seconds. Fixing the wrong code takes much longer. Second, give it a way to check its own work, like a test it can run. With feedback, it improves on each pass.

He also has advice for day one. Start with questions, not edits. Ask the agent how a piece of code is used, or why a function looks so strange, and let it dig through the history. Nothing changes, and you learn where its abilities end.

Another of today's writers suggests a trick I like. Do not write a five-hundred-word prompt. Write one line of intent and the criteria for success, then say, ask me questions before you start. You answer a few multiple-choice questions, and the gaps in your own thinking show up early.

Now, where does the analogy break? A field assistant who receives a vague protocol will usually come and ask. A reviewer might catch the problem before the season starts. A coding agent fills every gap with a confident guess and begins immediately. If you want questions and a plan, you have to ask for them.

In today's lab you will take three prompts you really sent recently, rewrite them as protocols, and run the old and new versions side by side. You will score each answer out of three. Then you will finish Unit Two by adding a short, how-to-work-here section to your capstone's map, so every future session starts with your protocol already in place.

Open your terminal, and let's write better protocols.
